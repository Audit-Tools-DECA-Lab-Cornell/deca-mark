## UI copy rules (owner: "anti AI slop; text must make sense from the user's perspective")
- Readers are field researchers and a professor managing a play-behaviour study. Write plain, specific sentences in their words: sites, zones, map packages, forms, rounds (Standard, Reliability, Inventory), observations, observers, team.
- Never show: fixture, preview, sample, demo, API, endpoint, server, session, token, payload, 404, null, undefined, UUID, slug (say "web address"), JSON (say "file" unless naming .geojson/.json files the user picks).
- No filler ("Seamlessly", "Effortlessly", "Unlock", "Powerful", "Welcome to your dashboard"), no exclamation marks, no emoji. Exact counts with correct plurals ("1 site", "26 observations"). Dates in the project's timezone.
- Empty states say what is missing and the one action that fixes it. Errors say what didn't happen ("Nothing was saved.") and why (`errorCopy`), and what to do.
- Not-available features: `<NotAvailable title="Deleting a project">` → "Deleting a project is not available yet." + one sentence why + what to do instead. Never a fake button.
- One magenta (primary) action per screen; secondary actions use `variant="ink"` or `"outline"`. Always pass `variant` explicitly on Button.
- State tags use the Contour state vocabulary (glyph + word + colour) from `contracts/contour.json` — never colour alone.
- Accessible: labels on every field, focus states kept, icon-only buttons have `aria-label`, tables have headers, 390 px layout works (tables become row cards or scroll inside their island, never the page).

## Facts about the API (verify against contracts/openapi.json and backend/src/fieldmaps_api/routers/*.py)
- Base: server env `DECAMARK_API_URL` (server calls), `NEXT_PUBLIC_DECAMARK_API_URL` (browser package transfer only). Bearer = the Supabase access token.
- IDs: org and project are UUIDs in the API. Web URLs: `/o/<org slug>/p/<project code>/…` (DECA Lab = `deca-lab`, Play Study = `play-study`). Map via `/v1/me` memberships.
- `/v1/me` → `profile {user_id, display_name|null, observer_initials|null, locale, created_at}`, `organization_memberships[] {organization_id, name, slug, role owner|admin|member}`, `project_memberships[] {project_id, organization_id, name, code, is_training, role manager|observer|viewer}`. No email (email comes from Supabase claims). Org owners/admins are reported as `manager` of every project in their org. Training project belongs to a platform org with no slug in memberships → hide `is_training` projects everywhere.
- 403 rules: `GET /v1/orgs/{org}` and `GET /v1/orgs/{org}/members` owner/admin only; project members & invitations lists managers only; drafts invisible to non-managers (404). Gate in the UI first, never call these for users without the role.
- Observations: `GET /v1/projects/{id}/observations?site=&round_type=&since=&limit=` (limit ≤ 500, default 500, newest `observed_at` first, `since` filters received_at, no cursor). `ObservationRow`: observation_id, site_code, site_name, form_version, coordinates [lng,lat], observer, observed_at, received_at?, zone, round_type standard|reliability|inventory, first_round bool|null, placement hand|zone, answers {questionId: value}, revision. `Site.observation_count` is the exact total. When a list returns exactly 500 rows, aggregates/exports must say "Based on the newest 500 observations."
- Sites: `Site {site_id, code, name, description, observation_count, package {package_id, version int, form_version, archive_bytes, archive_sha256, prepared_at}|null, zones [{id, label, west, south, east, north}], extent?, centre?}`. POST sites `{code, name, description?}`; PATCH `{name?, description?}` (code cannot change).
- Packages: list `GET …/packages?site=` → PackageSummary {package_id, version int, state ready|blocked, archive_bytes, form_version, prepared_at, site_code}; detail adds checks [{step, state passed|warning|blocked|skipped, detail}] and manifest. Archive `GET …/packages/{id}/archive` → zip (`manifest.json` + `layers/{ground,paths,trees,zones}.json`). A site's current package is its newest `ready` one (no activate step). Upload `POST …/packages` `{site_code, form_version, layers{ground,zones,trees?,paths?}, qgis_project?}` up to 24 MiB; server rejects a zone feature without `properties.id`.
- Forms: `GET …/forms` → FormSummary[] {form_id, code, name, versions[{version_id, code, version, state draft|published|retired, title, question_count, published_at}]}; POST `…/forms {code, name, definition}`; POST `…/forms/{form_code}/versions {definition?}` new draft (copies newest if no definition; legacy `shell-v1` cannot be copied → 409); GET/PUT/DELETE `…/form-versions/{code}` (PUT body `{definition}` on drafts; 422 with message on invalid); POST `…/form-versions/{code}/publish`, `…/retire`. Version code = `{form_code}-v{n}`. A definition needs ≥1 question. Publishing does not retire older versions. Authored JSON = `contracts/forms/janet-test-v1.json` shape; editor model in `W/lib/forms/definition.ts` (byte-identical to mobile; `pnpm forms:parity` — DO NOT edit `W/lib/forms/{definition,engine}.ts`).
- Team: `GET/POST/DELETE /v1/projects/{p}/invitations[/{id}]`, `GET /v1/projects/{p}/members`, `PATCH/DELETE …/members/{user_id}` {role}. Same for orgs (`/v1/orgs/{org}/…`, roles owner|admin|member). Invitation create body `{role, email?, max_uses?, expires_in_days?}` → InvitationCreated with `code` and `token` shown ONCE. Invitation list has no code, no inviter. Members: {user_id, role, display_name?, observer_initials?, granted_at} — no email. DECA Mark never sends email.
- Invitations: `POST /v1/invitations/preview {code|token}` → {organization_name, project_name?, role, expires_at}; `POST /v1/invitations/redeem {code|token}`.
- Projects: `GET/PATCH /v1/projects/{p}` (name, description, timezone, status active|archived — archived is not enforced; copy must only say it marks the project finished). `POST /v1/orgs/{org}/projects {name, code, timezone, description?}`. `PATCH /v1/orgs/{org} {name?, slug?}`; `POST /v1/orgs/{org}/transfer-ownership {user_id}`.
- Errors: `W/lib/api/errors.ts` — `ApiError{code, kind: sign-in|retry|rejected}`, `parseApiError`, `errorCopy` (safe local copy), `apiRequestError`. Never show server messages raw except validation messages from 422 on drafts.


## Backend handoff BE-17 (on master as 001e144; read `backend/WEB-FLOW-HANDOFF.md` — it is authoritative where it differs from the lines above)
- `GET /v1/projects/{p}/observations/{uuid}` (StoredObservation) now carries the full row context: project_id, site_code, site_name, form_version, received_at, zone, round_type, first_round, placement — even for records outside the 500-row list cap. Observation detail uses it directly, then fetches `form-versions/{form_version}` to label answers. NEVER interpret old answers with the newest published version or package.
- Legacy form definitions may carry `fields` instead of `questions`; answers/labels/export/codebook must support both (normalise once in `lib/observations/answers.ts`). A retired version's definition stays the historical definition; the row `state` is authoritative.
- List query: unknown query params are rejected (422) — send only site, round_type, since, limit. `since` is a received_at cutoff, not an observed-date filter. Browser-side zone/observer/date/search filters only see the returned subset; when the server list is limited (exactly 500 rows), say so even if browser filters show fewer rows.
- `Site.observation_count` is exact per site; sum for the project total only when every site is represented. Never compare that exact total with a capped/filtered report as if their scopes matched.
- Dates group by `observed_at` in the project's IANA timezone, DST-aware (no fixed 24h days). `received_at` is for upload activity. Legacy null round_type reads as Standard; null zone/first_round/placement stay null ("No zone" bucket kept in counts/exports, historical zones kept even if absent from the newest package).
- Coverage = records present by zone × round type, not completion. Timestamp-derived activity is not an audit log (don't call it one).
- New form returns its first draft. New version: POST `…/forms/{code}/versions` with `{}` copies the newest; `{definition:{}}` is 422. Concurrent publish/discard/create → 409 (copy: "Someone else changed this form. Reload to see the latest." + refresh); vanished version → 404.
- Packages: current = highest-version READY package per site; later blocked packages stay in history and cannot be downloaded. Upload ≤ 24 MiB body; stored archive ≤ 16 MB. Archive GET returns `application/zip` + quoted SHA-256 `ETag` (exposed via CORS); `Content-Disposition` is NOT exposed cross-origin — name downloads yourself, e.g. `${siteCode}-map-v${version}.zip`.
- Invitations: preview consumes no use; redeem is atomic; redeeming again as an existing member is an error (409 → "You are already on this project." style copy); preview+redeem share a per-user rate bucket → 429 with `Retry-After` seconds ("Too many tries. Wait N seconds and try again."); expired invitation → 410 ("This invitation has expired. Ask your project manager for a new one."). Send exactly one of `{token}` or `{code}`.
- Archive project = stored status only; not a lock; uploads still accepted. Copy: "Marks the project as finished. Observers can still upload records they already collected." Never promise it prevents collection.
- After membership/ownership/role changes: revalidate `/o` layout so `/v1/me` refreshes.
- Errors envelope `{error:{code,message,details?:{fields:[{id,problem}]}}}`: 401 sign-in, 403 denied, 404 absent, 409 conflict, 410 expired, 413 too large, 422 validation (show `details.fields[].problem` next to the matching field where the form has it), 429 throttled (Retry-After), 503 temporarily unavailable. DO NOT TURN A FAILED FETCH INTO AN EMPTY LIST — a failed read renders LoadFailure, never "No sites yet".
- Do not substitute any sample project or hard-coded user when a lookup is empty or fails.
