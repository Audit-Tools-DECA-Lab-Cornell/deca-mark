## Approved regression fixes

The full desktop/phone regression first returned **214 passed, 4 failed,
30 skipped** in 8.7 minutes. The previously blocked data list, recorded detail
and complete export passed on both widths. Two other blockers appeared:

1. The owner-authorized organization-member API returned an admin's
   `display_name: null` although the stored profile was `Local admin`.
   The profile SELECT policy allowed only own or explicit shared-project
   profiles. The user approved allowing organization owners/admins to read
   profiles of members within their own organization.
2. The invitation test expected “does not send email”, but the current disabled
   local delivery screen says “Email delivery is unavailable. Send the link or
   code yourself.” The user approved correcting this obsolete assertion.
   Real invitation creation, one-time link/code, redemption preview and
   revocation assertions are retained. The immediate API readback also raced
   the acknowledged revocation: the API first returned the old value, while
   the stored invitation then had a revocation timestamp. The readback now
   polls for at most ten seconds and still requires persisted revocation.

The RLS fix adds a same-organization owner/admin predicate to the current
baseline; existing own/shared-project rules, table grants and update policies
are retained. It was applied non-destructively only to the local test database.
No additional bypass role or security-definer function was introduced. The
authorization approach follows [Supabase's RLS guidance](https://supabase.com/docs/guides/database/postgres/row-level-security).

New SQL regression failed before the policy change:

```text
FAIL: org owner reads names of members without project membership
```

After the change, owner/admin access passes; cross-organization, viewer,
ordinary-member, Training and missing-identity access remains denied. SQL
fixtures and temporary role grants roll back.

The disposable baseline harness now applies the current baseline followed by
later feature migrations, including the existing email-outbox migration. Its
old exactly-one-file check incorrectly rejected that legitimate new migration.
This creates a fresh current schema; it does not convert old data or replay
the retired migration chain.
