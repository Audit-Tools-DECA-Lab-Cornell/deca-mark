# BE-20 local implementation and acceptance

> Historical evidence for the date/revision below. It is not a current task board or hosted-health check. See [current position and next work](../../plan/current-state.md) and the owning plans for later implementation and remaining acceptance.

Baseline: `92f8451bde8f195149bf9cb2afceee888cdd9826`, pushed to `origin/master` before
BE-20 began. This report covers the subsequent working-tree implementation. All fixtures
are synthetic. Hosted deployment, browser, physical-device and QGIS acceptance are separate.

## Result

V2 observation list, detail, summary and export share authorized server filters. Mixed
`observed_at DESC, id ASC` cursors bind to the project and normalized filters, while each
page's exact count and rows share one SQL statement snapshot. Later pages remain live reads.
Static summary/export routes precede the UUID detail route. V1 routes, array responses,
limits, serializers, hashes and receipts remain unchanged.

Reads join the exact recorded package and zone, preserving historical labels and form
definitions. Bound Inventory events have null geometry and an explicit snapshot display
anchor; legacy Inventory anchors are marked as compatibility data. Unknown legacy spatial
support stays unknown. Filtering, count and summary obey restricted-role RLS, including
Training ownership and separate sites with identical legacy zone codes.

Exports return an `application/zip` bundle with observations CSV or GeoJSON, `codebook.csv`,
`metadata.json`, `forms.json` and separate `historical-zones.geojson`. All assets derive from
one captured SQL snapshot. Frozen forms and polygons are deduplicated; no current package
pointer participates in attribution. CSV protects text and headers against formula execution,
keeps numeric coordinates numeric, distinguishes missing/null answers and preserves option
codes and dynamic-column routing.

## Operational bounds

The synchronous limits are 10,000 rows, 32 MiB combined uncompressed assets, 32 MiB ZIP
bytes and 10 seconds of work, with a separate 64 MiB source JSON budget. An oversized scope
returns structured 422 `export_scope_too_large` before any successful archive response.
Two serializer processes may run concurrently per API process; capacity exhaustion returns
429 with `Retry-After: 2`. Serializer children receive a minimal environment. HTTP disconnects
and deadlines cancel SQL/process work and release database sessions, temporary files and
capacity. Per-process capacity is not a global multi-replica limiter.

Signed loopback HTTP creates, edits, validates and publishes a package, captures against
that version, publishes a successor and reads/exports the historical record. A canonical
dynamic form travels through the real publication/detail/subprocess path with exact wire
definitions. Separate live tests disconnect the peer or expire the deadline, verify child
termination and temporary-file cleanup, then successfully export again. Additional cases
exercise tied timestamps, normalized cursors, incompatible scopes, DST half-open bounds,
historical renames, Inventory geometry and Training ownership.

Reproduce without persistent database credentials:

```sh
pnpm backend:check
pnpm backend:test ZONE_API_REHEARSAL=1
pnpm db:test ZONE_REHEARSAL=1
pnpm contracts:generate
pnpm plan:check
```

Use Node 24 and pnpm 10.17.1. Disposable rehearsals apply canonical migrations to their own
PostgreSQL 17/PostGIS containers and stop those containers on exit.

## Review

Fresh specification review identified four required corrections: codebook meanings when
historical versions/dynamic sets reuse a column; exact stored form JSON including extension
properties; unrelated answer columns named `observer`; and a cheap source-size preflight
before full SQL row rendering. All four source corrections passed fresh specification
re-review. The reviewer independently ran 28 domain/actual-budget tests. The final 73-test
focused run passed, including corrected SQL preflight, signed canonical extension-property
round trips and codebook/collision regressions.

Fresh code-quality review passed with no remaining findings. Its independent domain,
budget and dense subprocess run passed 32 tests in 3.49 seconds. A separate concurrency
harness verified the third active exporter receives 429 with `Retry-After: 2`; cancelling
two snapshot-stage tasks exits both transaction scopes and returns limiter usage to zero;
a subsequent real serializer process produces a valid ZIP. Authenticated predicates,
immutable joins, snapshot consistency and disconnect/deadline cleanup were inspected.
The final isolated full backend run passed all 678 tests in 368.15 seconds.

The first broad run passed 661 tests and failed the ordinary 10,000-row export at its
10-second deadline while another disposable database rehearsal ran concurrently. The
deadline returned structured 422 without partial success. It preceded the allocation
refactor and source-size gate. The final isolated full run passed after the focused rehearsal
finished, including the 10,000-row case. A preflight regression's initial count assertion included one extra legacy fixture;
its package filter was corrected without weakening the row-render sentinel.
