## Result

`PUT /v2/projects/{project_id}/observations/{observation_id}` validates a strict nested-answer
envelope against the exact historical package, site, zone and form role. PostGIS repeats
published-package, binding and inclusive point-coverage checks. Inventory stores its frozen
zone's server-derived compatibility anchor, with no submitted point or first-round field.
Superseded packages, retired frozen forms and archived projects accept authorized late work.

Both protocols check current authorization before recognizing an exact stored receipt and
before resolving mutable site/form state. V1 preserves its original serializer, hash and
wire receipt. V2 hashes the validated envelope before answer pruning with the frozen
`zone-upload-v2-jcs-1` JCS rules. Different owner, project, protocol or payload conflicts
without changing the stored observation. Historical rows without an authenticated owner or
hash also conflict safely rather than raising an internal error.

## Implementation boundaries

Collection routers remain thin and return receipts after transaction commit. Bound-upload
queries/repositories/services are separate from the shared receipt and answer-validation
modules. The request boundary rejects duplicate keys, invalid Unicode, unsupported encoding
and oversized bodies. RFC 6901 issue paths refer to submitted fields, without schema-union
labels. Capture times that overflow the supported UTC range return structured 422 errors.

The additive `20261011133000_zone_upload_protocol.sql` migration persists and freezes the
hash version. Its backfill leaves receipt times, revisions and other historical fields
unchanged. Upload authorization holds account then organization advisory locks and refreshes
access after waiting. The migration must run transactionally, as both rehearsal runners do:
its table lock protects the brief revision-trigger suspension during metadata backfill.

answers and compatibility anchor. A legacy read verifies committed data over HTTP.

Reproduce without persistent database credentials:

```sh
pnpm backend:check
pnpm backend:test ZONE_API_REHEARSAL=1
pnpm db:test ZONE_REHEARSAL=1
pnpm contracts:generate
pnpm plan:check
```

Use Node 24 and pnpm 10.17.1. Disposable rehearsals apply canonical migrations to their own
PostgreSQL 17/PostGIS containers and stop those containers on exit.

## Review

Both specification and code-quality review passed with no remaining required corrections.

Specification review passed after checking the strict envelope, frozen canonical bytes,
current authorization, historical binding, inventory role/anchor, v1 compatibility and
safe failure cases. It also verified the UTC-range correction through actual HTTP requests.
Quality review confirmed the focused module boundaries, authenticated receipt matching,
hash-before-pruning order and authorization locks. Its final correction makes the package
readiness predicate a strict SQL boolean. A database-valid old ready package with an empty
manifest reproduced HTTP 500 before the fix and now returns structured 422
`package_not_ready`, with no inserted observation. The affected legacy/binding/live suite
passed after this change; the 604-test full rehearsal preceded this final query correction.
