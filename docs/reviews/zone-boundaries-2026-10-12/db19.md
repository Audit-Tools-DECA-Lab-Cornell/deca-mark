# DB-19 current baseline acceptance — 2026-10-12

One canonical PostgreSQL 17/PostGIS baseline replaces the 24 incremental migrations.
Its ledger contains only `0001_current_baseline`. No persistent local or hosted database
was reset. The disposable runners remove only their own newly created test container.

## Concrete changes

Required observation package/zone references and same-site form/snapshot constraints
replace the old upload paths. Inventory stores null event geometry and null first-round;
GIS Inventory uses the exact retained zone polygon. Published snapshots, bindings,
publication results and current pointers remain immutable or transactionally guarded.
First uploads explicitly expect null, activate map v1, and use the same finalizer as drafts.

The baseline retains tenant RLS, account/organization authorization locks, Training
isolation/retention, Auth hooks and their 9,189 blocked-domain rows, restricted GIS roles,
and private function defaults. Package and check insertion grants are absent from the
runtime role. A narrow authorized metadata function lets package readers see source,
change note and publisher without exposing manager-only publication requests/audits.

Old preservation fixtures and the incremental rehearsal were removed. The GIS API
acceptance source now specifies map v1/v2 and the sole current upload/read contract;
its execution remains a BE-22 gate, because the Python runtime still needs replacement.

## Executed evidence

- `pnpm db:reset --disposable`: fresh baseline and seed build passed.
- `pnpm db:test ZONE_REHEARSAL=1`: passed from a separate fresh container, including
  application SQL, restricted Auth-hook tests, the verification SQL, 2,545 independently
  serialized coordinate comparisons, and the geometry JCS digest comparison.
- Seven observed-lock races passed: competing publications; identical retries;
  draft CAS; competing first null-precondition uploads; publication before revocation;
  revocation before publication; account forgetting before publication.
- The acceptance log contained 439 PASS markers. SQL checks include historical late
  upload, retired bound forms, point boundaries/holes/gaps, null Inventory, immutable
  attribution, direct-write refusal, all five validation changes and GIS tenant isolation.
- Shell syntax, Node syntax, whitespace checks and `pnpm plan:check` passed.

## Review and limits

Specification review found an obsolete GIS API fixture, which was replaced. Fresh tests
exposed missing global default privileges and a manager-only audit join hiding snapshots
from viewers; both fixes passed the final fresh run. Final source review checked fixed
search paths, narrow execution grants, membership-scoped publication metadata, same-site
foreign keys, authorization after waits, exact archive metadata, and replay before mutable
preconditions. No removed upload/legacy concepts remain in the baseline or SQL tests.
The form-definition `schema_version` is unrelated to the deleted upload discriminator.

The independent reviewer stopped at its usage limit and did not approve the final diff.
The lead completed the final specification/code review against the executed SQL evidence.
BE-22 must still prove the real API workflow and stable client-type generation. Browser,
physical-device, hosted Auth/PostGIS and QGIS Desktop acceptance are not claimed here.
