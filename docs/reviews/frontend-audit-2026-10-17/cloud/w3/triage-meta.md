# VERDICTS

## overall
Fit for a controlled pilot after roughly a week of targeted fixes, not before. The data-integrity core is well built and should not be touched: single-transaction saves, frozen upload bodies replayed by id, 'Uploaded' only from a matching receipt, exact map/zone/form version pinning, honest capped counts and LoadFailure states. What is not ready is the surface around it. The collector hides the answer input under the keyboard on phones, tells observers at sign-out and delete-account that it does not upload, and lets a double tap enter an answer nobody read. The web loses form-editor and settings edits on any failed Server Action, and blames the lab's own QGIS upload failure on zone rings. None of this needs a rewrite, a new state or query library or a hosting change. Every top item is a local change in one to three files.

## web_architecture
App Router use is sound and conservative. Routes are dynamic and per-user, reads share a per-request cache(), fetches are no-store, settle()/LoadFailure keeps failed reads honest, prefetch is deliberately off, and large uploads go browser-direct past the 2 MB action limit. There are two systemic gaps. Server Actions are assumed never to reject: about 17 feature files call them inside transitions with no rejection path, so offline, session expiry and deploy skew all land on a generic error boundary with false copy. Controlled text primitives also accept input before hydration. Loading boundaries sit one segment too deep, page-level failure handling differs between fresh load and client navigation, and old-route redirects, legacy service-worker cache names and the fields-only form reader are dead weight under the owner's policy.

## native_architecture
The storage and sync layer is the strongest code in the repo: serialized SQLite writes, atomic commit, account fences, verified staged installs and no-substitution recovery. Its React wiring is weak. Memos are keyed on the session object, so a token refresh cancels downloads. A 5-second tick bumps a revision whether or not anything changed. Retry backoff outlives reconnect. The collect layout uses two different trees, so rotation remounts the map. The release Observations tab is still the legacy Nocturne screen with its own vocabulary. The frozen 'legacy' owner scope and the write-only tables should go in one sanctioned schema bump. The schema reset itself is policy, but it needs an explicit end date before real records exist.

## performance
The web is fast where it was measured: TTFB 12-57 ms, CLS 0 on 30 routes, and no long tasks on 29 of 30 routes in the lab. The one demonstrated defect is a warm tab-switch floor of about 250 ms, caused by loading.tsx remounting under React 19.3's 300 ms reveal throttle. A controlled experiment verified a one-file fix. On hosted latency the cost mostly shrinks to a skeleton flash. Data at 500 rows is the heaviest page (15.2k nodes, 2.2 MB HTML, 944 ms of long tasks at 4x CPU over n=2), and about a third of that is the duplicated card list. zod on every /o page and supabase-js bundled three times are cheap wins, not urgent. Server N+1 and per-render archive unzip are negligible at pilot size. Mobile costs (full-table re-reads every 5 s, unbounded lists, re-verification) are unmeasured on Hermes and should be timed on the pilot device before anyone optimizes.

## ux
The manager UX is honest about caps, time zones and scope, and that care shows. It breaks where separate objects meet. A blocked upload is blamed on zone rings. The Forms list and Overview hide which form version observers actually get, and the upload step defaults to the older version. Delivering a new version needs a full QGIS re-upload. The collector's placement, recovery and readiness UX is strong, but the answer-and-save loop has defects that cost data on phones: the keyboard covers the answer, a double tap answers the next question, the Saved step's forward button is below the fold, and draft write failures are hidden behind a hard-coded 'Draft kept' line.

## accessibility
Web accessibility is genuinely good. axe found 0 violations in 60 journey runs and in 10 Forms runs, and the skip link, route focus, keyboard-complete zone editor and global reduced-motion rule all work. The real web defects are small and sit in shared code: 13 dialogs do not return focus, the password toggle fails label-in-name, and single-key shortcuts fail 2.1.4. Native primitives are good, but the release Observations tab sits outside them, VoiceOver gets no live placement readout, the map camera ignores Reduce Motion, and the promised preferences exist only in dev builds. No assistive-technology run on a real device has happened, so every native accessibility claim is code-derived.

## testing
Test quality is high and wiring is poor. CI does not run the 393 web unit tests, forms:parity or the token check, although they take about 6 s and the docs say CI runs them. The real collector-to-API acceptance driver is orphaned, and there is no native runner. As a result, every collector defect in the top five was found by hand or on the simulator, not by the suite. The e2e suite is solid (134/134 on desktop), but settings.spec fails about 25% of the time. That flake is a real hydration defect plus a test race, not noise. Screenshots run in five projects by default. Fix the wiring first (about an hour), then add the four tests that would have caught the top defects.

# POLICY
- Schema reset (MOB-REC-01, S1, TEST-04): the binding decision makes the SQLite wipe on a SCHEMA_VERSION change sanctioned, not record loss. I moved these from critical CONFIRMED DEFECT (original) and medium DESIGN PREFERENCE (Mac) to low DESIGN PREFERENCE. Launch gate: before any device holds real research records, freeze SCHEMA_VERSION for the pilot or add the refuse-if-unsent guard. After that point the same behaviour is critical record loss.
- Frozen 'legacy' owner scope and write-only tables (MOB-REC-07, MOB-REC-09, S6, MFD-9): the policy turns S1's 'cannot be removed safely' into 'remove with one sanctioned schema bump'. MFD-9's 'do not bump SCHEMA_VERSION' caution no longer applies.
- Old-install and old-name compatibility (WEB-R8, S5, NEW-LEGACY-REDIRECTS, N-5, TEST-07, migrateLegacySession, the 'fieldmaps' scheme, the legacy SW cache names): all are deletion material, rated low DEMONSTRATED COMPLEXITY. None is a defect, and none needs an upgrade path.
- Fields-only form reader (S4, the web half of MFD-9, part of WEB-R8): the Mac pass refuted S4 because commit b93a2b2 restored the reader to preserve hosted data. Under this audit's binding decision (old formats are deletion material and server data may be reset), it moves to deletion. It is flagged as an open question because hosted rows and the backend half (legacy_forms.py) are outside this frontend audit.
- Runtime versioning is a product feature, not complexity to cut. Records keep their package, zone and form version; recovery refuses substitution; the Data map shows one version and dims the others; packages name exact form versions. UXW-4's full re-upload is the price of that rule, and any rebind action must keep it.
- Unreadable persisted rows (MOB-REC-03, UXC-05 trigger a): under the bump-and-reset policy they arise only from a developer slip (a schema tightened without a bump). Per-row safeParse hardening of every table is therefore not warranted. A discard card for an unreadable draft is cheap insurance and stays in C08.
- The '.dev' bundle id shared by every environment (MOB-REC-07) is only configuration hygiene, since every installed device is a development device. A distinct production id is needed before any store submission.
- The policy does not soften C02. The false 'does not upload' and 'cannot upload them first' copy concerns records the policy never meant to drop, so it stays high.
- Being pre-launch lowered process-only findings by one step (TEST-01 high to medium, TEST-02 to low after NEW-TEST02-CI), because nothing is failing today.
- Data the runtime passes changed (the uxw2-clean project, v5 published in web-acceptance, description edits) is synthetic, and resetting it is fine.

# NEXTJS
Capabilities that would solve a demonstrated problem here:

1. **Placement of loading.tsx and Suspense boundaries.** Move p/[project]/loading.tsx up to p/loading.tsx (or put one Suspense in p/[project]/layout.tsx), and do the same for (org)/loading.tsx. This removes the measured warm tab-switch floor: build A took 327-360 ms, F 79-205 ms and G 74-201 ms on overview to data, data to sites and site to forms, and the cold skeleton is kept. Once tab switches stop showing a fallback, use next/link useLinkStatus (present in 16.2.7) on InkTabs, so a slow hosted RSC response still shows a pending state. Prefetch must stay off.

2. **unstable_isUnrecognizedActionError (next/navigation, 16.2.7) inside the settleAction helper.** It lets the form editor answer a deploy-skew Server Action failure with 'DECA Mark was updated…' instead of crashing into the error boundary (C03). The deploymentId config alone only forces a hard reload on a version mismatch, which also drops unsaved edits. If the web is hosted on Vercel, Vercel Skew Protection is the hosting-side complement: it keeps old tabs' actions resolving against their own deployment. It is a project setting, not a migration.

3. **Server Actions passed to `<form action>` with useActionState.** These would make a Save or sign-in pressed before hydration POST to the action instead of doing a native GET (HYD-4), and would read DOM FormData. The account form already works this way and keeps pre-hydration text. They do not stop React from overwriting the textarea at hydration, so the useHydrated gate in the four primitives is still the smaller and complete fix. This is optional for sign-in only.

No justified benefit here:
- **Cache Components, PPR, 'use cache', unstable_cache and staleTimes.** Every route is per-user, cold TTFB is 12-57 ms, and the measured cost is API fan-out, not rendering. Caching per-user research data would also break the 'refresh shows the API's current state' guarantee.
- **Turning prefetch back on.** The 0 measured prefetch requests are a deliberate way to protect the API.
- **next/image.** There are no raster images.
- **Edge runtime, ISR or middleware rewrites.** Nothing measured needs them.
- **React Compiler or memoization sweeps.** The only measured render cost is the duplicated Data list (C18), and the fix is structural.
- **A client data cache or query library.** No-store plus revalidatePath is correct.
- **Virtualization.** Not needed at the 500-row cap.

Current choices that are right:
- Dynamic per-user rendering with request-scoped React cache().
- settle() with LoadFailure.
- Browser-direct uploads past the 2 MB serverActions bodySizeLimit.
- proxy.ts local ES256 getClaims.
- Suspense around Overview's Coverage section.
- revalidatePath after mutations: it also evicts the client bfcache, which is why saveDraftAction's revalidate must stay.

The measured server costs to revisit only after hosted measurement are Overview's per-site listPackages N+1 (a 216-253 ms stage at 10 sites, 4.2-4.5 s of summed API time at 28) and the serial awaits on the form editor and publish pages. Both are fixed with Promise.all and earlier promise starts, not with a Next.js feature.

# JUSTIFIED
- prefetch={false} on workspace links: 0 prefetch RSC requests across 31 links, which keeps per-link proxy and /v1/me fan-out off the API. Keep it, and add useLinkStatus feedback rather than turning prefetch on.
- No server data cache: API fetches use cache 'no-store', and React cache() only de-duplicates within one request. For per-user research data, a refresh always shows the API's current state.
- settle()/Result with LoadFailure: a failed read renders a designed failure state, never an empty list. Where a page breaks this rule (C16) it is a local bug, not a reason to change the pattern.
- Intl formatting fixes locale en-US and the project time zone, and nowIso is computed on the server: SSR and hydration produce identical text, and CLS was 0 on all 30 routes.
- Package uploads, exports and downloads go browser-direct to the API (bodies up to 24 MiB) instead of through Server Actions (2 MB limit).
- Hand-written SVG site plans on the web instead of a map library: no map dependency in any bundle, and 500 markers and 250 zones are within SVG's comfortable range.
- MapLibre stays mounted across collect steps with an imperative camera, and prior observations are drawn as GPU circle layers with a simple grid cluster, so no clustering library is needed.
- A byte-copied form engine checked by a parity script, given that each app owns its own lockfile. It is the cheapest way to share the engine, but it must run in CI (C13).
- Per-platform Contour primitives over one token contract (contracts/contour.json), and per-platform error tables typed 'satisfies Record<ErrorCode, string>'.
- Radix for dialogs, menus, popovers, toasts and form controls, and InkTabs as a nav of links with aria-current rather than role=tab.
- Mobile uses ky with generated types for the API and supabase-js only for auth: one stack per concern.
- Records are saved in one transaction, the upload body is frozen and replayed by a client UUID, and 'Uploaded' comes only from a matched receipt; aborts caused by backgrounding are not counted as attempts.
- Crosshair placement with nudge buttons, tap-to-aim and a live in-zone readout, and validation only at Review: the right design for gloved, distracted field use.
- Counts are honest about the 500 cap, with 'Show the next 500'. Paging plus server totals make virtualization unnecessary at pilot scale.
- No Cache Components, PPR or 'use cache': every route is per-user, and the measured cost is API fan-out, not rendering.
- ES256 local JWT verification (getClaims) in the proxy with a module-global JWKS cache: no auth round trip per request.
